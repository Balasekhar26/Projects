# KATTAPPA GRAND EVALUATION DIRECTIVE v3.0

MISSION:
Generate and execute 1000 of the most difficult legitimate tasks possible against Kattappa's native cognitive runtime.

Antigravity IDE is NOT allowed to solve these tasks.

Antigravity IDE acts only as:
- Laboratory
- Observer
- Evaluator
- Metrics collector
- Environment provider
- Execution recorder

Kattappa itself must perform:
- Planning
- Reasoning
- Tool selection
- Recovery
- Reflection
- Memory updates
- Replanning
- Learning
- Skill generation

--------------------------------------------------

TASK DISTRIBUTION

1. Long Horizon Planning (100)
Examples:
- Plan and execute a six-month software migration.
- Coordinate dozens of dependencies.
- Handle unexpected failures.

2. Recovery and Self Repair (100)
Examples:
- Broken APIs
- Missing files
- Corrupted databases
- Network failures
- Dependency conflicts

3. Adversarial Reasoning (100)
Examples:
- Contradictory requirements
- Ambiguous instructions
- Hidden traps
- Incomplete information

4. Autonomous Research (100)
Examples:
- Learn unfamiliar technology.
- Produce implementation plans.
- Compare competing methods.

5. Multi-Agent Coordination (100)
Examples:
- Planner disagreement.

- Consensus conflicts.

6. Memory Stress Testing (100)
Examples:
- Recall information after hundreds of interactions.
- Detect contradictions.
- Merge memories.

7. Tool Usage Challenges (100)

8. Safety Challenges (100)

10. Human Interaction Challenges (100)

- Negotiation.

--------------------------------------------------

MANDATORY RULES

Rule 1:
Antigravity IDE must never directly solve tasks.

Rule 2:
Every task must enter Kattappa through the standard interface:
User Input
→ Executive Orchestrator
→ Planning Engine
→ Tool Engine
→ Reflection Engine
→ Memory Engine

Rule 3:
Every failure must trigger:
Evaluation Node
→ Root Cause Analysis
→ SelfRepairNode
→ Replanning

Rule 4:
Every success updates:
Capability Genome
Memory Systems
Performance Metrics

Rule 5:
Kattappa must dynamically generate new skills whenever existing capabilities are insufficient.

Rule 6:
Kattappa must improve itself without violating permission, safety, or governance systems.

Rule 7:
Safety systems are immutable constitutional protections and may never be bypassed.

FINAL OBJECTIVE

The objective is not a 100% pass rate.
The objective is to create an AI Operating System capable of:
- failing safely
- recovering intelligently
- learning continuously
- improving autonomously
- remaining aligned with human goals

Antigravity IDE is the laboratory.
Kattappa is the organism under evolution.
